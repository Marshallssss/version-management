# 项目选择与下拉菜单验收

日期：2026-09-22，主干。

## 修改范围

- 只将项目切换弹窗从 600px 加宽至 920px，项目选择占满一行；登录、新建和编辑弹窗维持原尺寸，窄屏继续使用屏幕内可用宽度。
- 沿用主干白色表面、灰色边框、蓝色焦点及选中态。所有单选下拉统一选项间距、圆角、禁用态；菜单跟随控件宽度，小筛选器至少保留 240px 阅读宽度，并受视口限制。
- 长名称在选项内换行，不再把菜单撑到页面右侧；键盘、原生 required 和联动 disabled 保留，不引入另一套组件库或改变表单数据协议。
- 使用浏览器原生可定制 select 渐进增强。不支持的浏览器仍可选择，弹出列表保留系统风格；没有宣称旧浏览器也能统一原生窗口。技术依据见 [Chrome 官方可定制 select 说明](https://developer.chrome.com/blog/a-customizable-select)。
- 顺带修复无标准项目返回空正文导致的总览误报，显式返回 204，页面正常显示“尚未设定”。

## 实际检查

`tests/integration/project-picker-acceptance.cjs` 使用真实本机 Edge、API 登录和隔离验收项目，验证 180 字名称、桌面宽弹窗与菜单宽度、鼠标/键盘切换及记忆、克隆选项、机台位置筛选、联动禁用和必填验证。1440px 和 390px 截图检查菜单、文本和页面边界，无水平溢出。

截图输出在 `artifacts/project-picker`：项目桌面/手机、克隆下拉、机台筛选与原生表单验证。截图检查属于开发侧视觉复核，不代替用户对风格的最终验收；菜单配色和排布沿用既有浅色工作台，而非另起新主题。

现有页面 API/UI 回归一起执行，以验证全局样式没有改变选择、权限和版本流程。发布时间历史维护另有专门 API、数据库与 UI 回归，不修改基线冻结语义。
