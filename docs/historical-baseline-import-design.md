# 历史基线 Excel 导入设计

状态：2026-09-22 方案分析，尚未实现。现有导入仍只登记测试版本；不会因本文件自动开放历史发布。

## 1. 同一模板，两种记录

保留当前每列一套配置、组件在左侧、根组件分组的方向；不再要求用户切换两种完全不同的表格。模板升级为 v3，“测试组合 1”改为“配置记录 1”。

| 字段 | 测试版本 | 历史基线 |
| --- | --- | --- |
| 记录类型 | 下拉选择，默认测试版本 | 显式选择历史基线 |
| 记录日期 | 必填，YYYY-MM-DD | 保留来源记录日期，不替代发布时间 |
| 说明/原因 | 必填 | 必填，说明历史评审及补录依据 |
| 基线名称 | 不填 | 必填，不静默覆盖同名记录 |
| 发布时间 | 不填 | 必填，YYYY-MM-DD HH:mm，例如 2025-06-12 14:30 |
| 组件版本 | 填写表示变更，空白保持不变 | 每个有版本意义的组件必须填写，空白报错 |

模板显示并固定业务时区，默认沿部署配置明确标注 Asia/Shanghai（UTC+08:00），服务端转换为 UTC；不依赖导入操作者电脑时区。基线发布时刻不晚于当前时间，范围沿现有历史维护规则。

测试列误填基线名称/发布时间应报错，不能把本想导入的历史基线静默登记为测试。旧 v1/v2 模板仍只按原测试语义解析，不根据内容猜测记录类型。

## 2. 完整性及历史事实

- 核对当前项目、模板绑定、组件标识和所属项目，不能用重名匹配绕过项目校验。
- 历史基线核对模板与当前完整组件集合、父子关系及分类属性；结构变化时要求重新生成模板。结构分类节点保留树快照、不需要版本，有版本意义的根组件必须填版本。
- 版本必须属于对应组件，版本号按原字符串匹配，不解析排序、不丢失前导零。完整结果预览为与基线页一致的组件树。
- 首片建议仅引用已经登记的已发布/维护中且未阻断版本。未知版本、测试版、草稿版、废弃版或阻断版明确列出问题；不能在导入过程中悄悄发布、恢复或改变安全状态。这是首片范围限制，不意味着那些版本历史上没有真实存在过。
- 没有历史版本的组件不能拿空白或结构分类节点冒充“当时未配置”。若过去的组件集合不同，需先明确“不适用/尚未引入”的快照语义，再扩展模板，不勉强生成不真实的历史。
- 历史列独立完整，不从当前项目标准或前列补齐；它也不改变后续测试列的继承链。测试列只继承前一成功测试记录，首次继续使用模板冻结的参考配置。

## 3. 预览与自动扫描

历史基线只允许 Admin/SuperAdmin 手动操作：上传 -> 校验 -> 按记录类型分组预览 -> 显示完整快照及发布时间 -> 确认导入。普通测试扫描保持原有权限。

每日扫描不自动发布历史基线。遇到尚未人工确认的历史列，本轮不写入新内容，明确提示“包含历史基线，请管理员预览确认”；人工导入后，扫描通过固定记录标识和内容指纹跳过已完成列，继续测试增量。这样不会静默忽略历史，也不会无人值守改变发布事实。

错误定位到具体配置列和组件名称；历史基线缺版本属于阻断错误，不照搬机台资料导入的“版本留空仍成功”。

## 4. 时间、领域命令与冻结

- `CreatedAt` 是真实导入时间，`ReleasedAt` 是填报的历史发布时间，审计发生时间仍为现在。
- 新建独立的历史基线导入命令，明确历史来源；不能将 `MatrixImportService` 的 Testing 新版本登记和普通 `CreateBaselineAsync` 直接串联。前者会废弃原测试版本，后者会默认选最新发布版并用现在作为发布时间。
- 导入仅调用受控领域命令；统一权限、actor、reason、correlation 和 idempotency。预览保存规范化内容和指纹，提交时重新校验权限、组件、版本资格及指纹。
- 同一提交批次的新内容同成同败；固定列标识、类型和规范化内容参与重复判断。重复导入无副作用，改写已导入列报告冲突，不更新旧基线。
- 已导入历史仍冻结；不自动设为项目标准，不改变机台目标/实际，不废弃当前测试版，不制造 Lab 上机或验证证据。历史补录不伪造普通“刚发布”事件，不开放普通三分钟撤回窗口；纠错使用现有超级维护保护。
- 若以后允许补录尚未登记的历史版本，必须单设受控历史登记命令，保留真实创建时刻与历史来源，禁止绕道 Testing 影响实验室状态。

## 5. 实施切片及验收

1. 模板 v3、明确字段与格式、解析/项目/全组件校验、旧模板兼容、只读树形预览。
2. 历史领域命令、保存来源与审计、前进 Migration、管理员确认与事务幂等、冻结及时间语义。
3. 混合文件扫描隔离、中文定位、失败恢复、自动化回归和真实 Excel/浏览器视觉验收。

每片完成数据库/应用/API/UI/测试闭环。重点自动覆盖：两种空白语义、混合列继承、跨项目、过期组件树、分类变更、缺版本、无效时间、未知版本、权限回收、重复及篡改扫描、批次回滚、历史导入不影响当前 Testing/Lab/项目标准/机台实际与目标。

## 6. 实施前确认

建议先按上述保守范围交付，以下需求不能默认为已支持：

1. 是否需要一起补录软件里尚未登记的历史版本？若需要，扩大第二片的历史登记命令，不要求先变成测试版。
2. 是否存在历史上还没有引入、现在却已存在的组件？若有，应增加明确的历史适用范围，而不是强行填一个当前版本。
3. 是否需要归档现在已废弃/阻断、但过去确实评审发布的版本？若需要，区分“真实历史归档”和“当前可部署资格”，增加超级权限确认和醒目风险标记，不能默认解除风险。
