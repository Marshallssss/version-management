# 历史基线 Excel 导入

## 使用方式

在“版本导入”生成新版项目模板，每列是一套“配置记录”，左侧组件路径和根组件分组与项目组件树对应。旧 v1/v2 模板继续支持原测试导入；历史记录需要重新生成 v3 模板。

| 填写项 | 测试版本 | 历史基线 |
| --- | --- | --- |
| 记录类型 | 留空或选择“测试版本” | 选择“历史基线” |
| 记录日期 | YYYY-MM-DD，必填 | 可留空，取发布时间对应日期 |
| 变更说明 | 必填 | 必填，写明历史评审和补录依据 |
| 基线名称 | 留空 | 必填，项目内不能重复 |
| 发布时间 | 留空 | YYYY-MM-DD HH:mm，北京时间，例如 2020-01-02 08:30 |
| 组件版本 | 填写表示变更，空白沿用 | 每个有版本意义的组件必须填写 |

时间和版本输入区域采用文本格式。粘贴时保留模板格式，避免 Excel 将 `001.02` 自动转成数字。历史发布时间范围为 2000 年至当前时刻，存储时统一换算为 UTC。结构分类节点保留层级快照，不填写版本；特殊缺项明确写“当时未配置”，空白不能代替。

管理员选择文件、填写本次录入原因，点击“历史基线预览”，校验后逐条查看完整组件树、名称、发布时间、补录版本和当前风险，再勾选确认并提交。确认仅录入文件中的历史列；混合文件中的测试列随后通过“扫描并录入”登记。

## 历史语义

- 未登记的历史版本通过历史登记命令创建为“已发布”，版本创建时间取该版本在本批历史基线中最早的发布时间。版本号按字符串匹配，保留前导零；历史补录序列排在现有实时序列之前，避免成为默认最新发布版本。
- 已登记版本保持原创建时间、成熟度、安全状态和推荐状态，包括当前测试、废弃或阻断版本。历史基线项单独记录“历史已发布”；界面同时展示当前状态和阻断风险。
- 基线的发布时间来自 Excel，基线自身创建时间、导入记录和审计时间为实际录入时刻。历史记录不会制造实验室验证、上机或软件安装事实。
- “当时未配置”是明确的快照状态，与结构分类节点、未知和未指定版本不同。机台比较中实际明确缺席可匹配，实际存在则为额外配置，尚无观察记录则为未知。
- 历史导入不会自动切换项目标准或机台目标/实际，也不会废弃当前测试版本。历史基线遵循既有冻结保护，不开放普通三分钟发布撤回窗口；后续纠错仍使用既有超级维护权限。

## 校验与扫描

模板绑定项目及组件标识，禁止通过同名组件跨项目匹配。新历史列要求当前组件集合、父子关系、分类属性、名称和顺序与模板一致，变化后需重新生成模板。每个有版本意义的组件必须提供版本或明确缺项，至少保留一个实际版本。

预览不会写入业务版本或基线。提交时重新检查管理员权限、组件/版本信息及预览指纹，过期预览需重新确认。同批历史记录在一个事务内提交，失败不留下部分基线。固定列标识与内容指纹保证重复确认/扫描无副作用；已导入列不能改写，也不能从历史改为测试或从测试改为历史。

每日扫描和手动普通扫描遇到未经管理员确认的历史列，会报告原因且本轮不录入任何新内容。人工确认后，原样历史列会被跳过，测试列继续按原测试继承链处理；历史配置不会成为后续测试列的隐式参考。

## 部署与验收

新增真实 EF Migration：`20260922155138_HistoricalBaselineExcelImport`。其他部署环境应先备份并按现有升级流程应用全部待执行迁移，然后启动 Host/Worker；不要修改已经执行过的 Migration。

自动验收入口：`tests/integration/historical-import-acceptance.cjs`。覆盖真实 XLSX、全组件/时间/项目校验、历史补录时间、权限与幂等、混合扫描、当前配置隔离、冻结保护、过期预览及桌面/手机确认流程。原测试模板与扫描回归继续由 matrix 系列验收覆盖。

本机 PostgreSQL 17 的开发验收不替代目标 Windows 的 IIS、服务账户、TLS、共享文件和备份恢复验收；**Production Integration Pending** 保持不变。
