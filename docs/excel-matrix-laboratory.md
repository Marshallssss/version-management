# 项目 Excel 台账与实验室验证

适用版本：2026-09-18 主干更新。该功能登记版本与实际配置记录，不会向机台自动安装软件。

## 1. 生成项目模板

1. 在顶部选定项目，先维护好组件名称、父子关系与排序。
2. 进入“导入”，点击“生成项目模板”，填写原因后下载。
3. 在 Excel 中填写“版本登记”工作表，从 D 列开始，每一列填写一套版本。

组件按项目树顺序纵向排列在左侧 B 列，每个根组件使用深色分区；自身有版本的根组件也有版本输入行。没有任何已登记版本但有子节点的组件仅作为分类，空叶节点可以登记第一个版本。表头含完整组件路径，隐藏标识负责准确绑定，不按相似名称猜测组件。上方日期/说明与左侧组件/参考列均冻结，横向浏览更多组合时仍能看清归属。

C 列是生成时冻结的项目标准参考，没有标准或未覆盖组件显示“尚未指定”。以后项目标准改变，不会悄悄改变此模板的继承起点。希望使用新标准时，应重新生成模板并明确切换扫描源；旧组合继续保留。

## 2. 每列只填写变化

示例：冻结参考为主控 `V1.0`、驱动 `V2.0`、界面 `V3.0`。

| 左侧表头 | 冻结参考 | 测试组合 1（D 列） | 测试组合 2（E 列） |
| --- | --- | --- | --- |
| 记录日期 | | 2026-09-18 | 2026-09-19 |
| 变更说明 | | 修复通信超时 | 驱动联调 |
| 主控 | V1.0 | V1.1 | |
| 驱动 | V2.0 | | V2.1 |
| 界面 | V3.0 | | |

第一套结果为 `V1.1 / V2.0 / V3.0`；第二套为 `V1.1 / V2.1 / V3.0`。留空不是删除，也不是选最新版本，而是沿用前一成功组合。组合是测试台账，不是已发布基线。

- 第 5 行记录日期使用 `YYYY-MM-DD` 文本，例如 `2026-09-18`，表头与输入提示均给出格式。它只表示该组合的业务日期，不冒充软件安装时间或系统实际录入时间。
- 第 6 行变更说明必填，最多 500 字，作为本列新增版本的登记原因；版本号最多 160 字，作为完整文本保存，包括 `001.02`、`.` 和普通空格。
- **新版不再有提交标记。** 同列至少填写一个版本、有效日期和说明，保存后即可被手动或每日扫描录入。启用自动扫描的文件请只保存准备提交的完整内容。
- 完全空白的列忽略；任何已开始填写但缺少版本、有效日期或说明的列会使本轮整体失败，不跳过半成品去继承后面的配置。
- 请在已有空白列中填写，只复制可见输入区的值；不要整列复制覆盖隐藏标识，不要修改冻结参考、隐藏行/列或自行添加组件行，分类标题行不填版本。新增组件后生成新模板。
- 不使用公式、宏、外部链接或自动转换后的数字/日期作为版本号。来自其他表格的数据请粘贴为文本值。

单份模板最多 2000 套组合、496 个版本组件，文件上限 10 MiB。当前只支持本系统生成的 `.xlsx`，不支持任意外部表格、旧 `.xls` 或宏工作簿。

旧版 v1 模板仍按“组件为列、每行一套”解析，继续要求原“可导入”标记，避免升级后把旧草稿自动提交。重新下载模板得到新版 v2；不要将新旧台账的隐藏标识混合粘贴。需要迁移未完成内容时，填写新版空白输入区即可。

## 3. 录入与冲突处理

手动录入：选择对应模板及填好的文件，填写本次录入原因，点击“扫描并录入”。该按钮直接登记有效的新组合，不是只读预览。选择文件本身没有副作用。

- 新版本通过与页面相同的版本命令登记为“测试中”，生成审计与状态历史，不直接写业务表绕过规则。
- 已存在的同组件同号版本仅引用，不把已发布/已废弃版本重新改成测试中。
- 同组件只允许一个测试版本；后续新测试版本会将旧测试版本标记为已废弃。旧组合完整快照不变，已安装旧版本的 Lab 机台不会自动更新。
- 重复扫描跳过已录入组合。已录入内容的日期、说明或版本改变会失败，请还原并在右侧追加新列。
- 每轮新内容同成同败；任何新组合无效，本轮均不录入，已有历史不回滚。修正 Excel 后重新扫描即可。
- 删除 Excel 列不会删除系统历史。不要把旧台账当作可覆盖更新数据库的工具。
- 扫描结果显示具体“组件 从旧版本变为新版本”，点击后定位对应测试组合的组件；变更前后版本与浅红背景同时展示。组合保存完整组件层级、名称、版本号和来源位置，之后改名不会覆盖历史。
- **Admin / SuperAdmin 可在版本页删除仅被 Excel 引用的误登记版本**，需二次确认及原因；模板/组合快照仍保留原名称、版本与来源，标记为已删除且不再链接已删版本。受基线、机台事实、Lab 验证或风险快照引用的版本仍不能删除，组件自身的引用保护不变。
- 重扫已录入组合不会恢复被删版本。如果下一套新组合会继承已删版本，必须在该列明确填写正确版本后才能继续录入，不会静默替换。管理员也可将已废弃版本恢复为测试中，同组件旧测试版随之废弃，留下原因和新一轮测试历史；安全状态不会被清除，非管理员无此权限。

页面显示最近 200 套组合及 100 次扫描；扫描记录中的变更链接可打开不在最近 200 套列表中的原组合。更早数据库记录仍保留，本片没有分页查询界面。

## 4. 每日固定文件扫描

管理员在“扫描设置”中选择模板，填写服务器可访问的完整路径、每日时间和时区，开启后保存。例如 `D:\ConfigHub\imports\项目台账.xlsx`，或获授权的 UNC 共享路径。

路径属于运行软件的部署电脑，不是浏览器所在电脑。保存设置时会验证文件与所选模板匹配。只有管理员能配置或手动扫描服务器路径；手动上传录入需要全局高级工程师及对应项目高级成员权限，Admin/SuperAdmin 可操作。Viewer 无录入权限，接口也会拒绝。

安全与运行条件：

- **能修改该固定文件的人，等于能提交该项目的测试版本录入。** 新模板不再二次勾选提交标记，只给可信工程师共享写权限；Host/Worker 服务账户只需读取该文件，不需要修改权限。软件审计记录扫描执行身份与授权管理员，不会伪称已识别每列 Excel 的实际编辑人。
- Windows 服务常看不到交互登录用户映射的盘符，共享文件请使用 UNC 路径；实际服务账户需要共享和 NTFS 两层读取权限。
- Worker 每 15 秒检查到期源，按设置时区每日扫描，浏览器可以关闭。暂停会停止自动排程，管理员仍可用“立即扫描”明确触发一次。
- 保存文件后再扫描。软件会稳定读取且不回写工作簿；临时文件 `~$...xlsx` 不作为来源。文件正在保存、共享断开等读取失败会记录结果并约 5 分钟后重试；内容校验错误按下一次每日扫描或手动重试处理。
- 授权管理员失去权限或项目归档后，后台不再录入；权限失效的源暂停，需要管理员重新确认保存。进程异常沿用现有后台任务租约/重试机制，不重复登记成功记录。
- 查看“导入 → 扫描记录”的业务结果。后台队列任务完成表示扫描处理已结束，不保证 Excel 内容全部有效；内容问题会显示“扫描失败”及中文原因。

Windows 服务部署继续使用既有 `ConfigHub.Worker` 服务。源码本地运行的 `start-local.cmd` 目前只启动 Host；要使用每日扫描，还需在仓库根目录启动 Worker 并保持运行：

```powershell
dotnet run --project src/server/Worker/ConfigHub.Worker.csproj -c Release --no-restore
```

首次使用前需要按原离线/公司源配置恢复 Worker 所需包。本次未增加第三方 NuGet/npm 依赖。本机已启动 Worker；换电脑时不要只验证网页可打开而漏掉后台服务。

## 5. 从测试版本到 Lab 验证

1. 在机台页将实际用于测试的整机或已安装 PM 阶段设为 `Lab`。
2. 在版本页的实验室树中点击“测试中”右侧的“未上机 / 已上机”标记，打开右侧“Lab 使用与验证”。
3. 真实升级完成后，选择 Lab 整机或 PM，填写实际升级时间与原因，点击“记录已完成的升级”。单次只登记当前组件，其他实际组件、其他 PM 特例、机台目标和项目标准保持不变。
4. 完成验证后选择实际使用该版本的范围，填写“待验证 / 验证通过 / 验证失败”、实际验证时间及说明。时间支持秒精度，不能早于实际升级或本轮版本进入测试的时间。
5. 按原状态发布或“从测试版本创建基线”流程发布。版本发布和整体基线仍是不同操作，基线不会自动成为机台目标。

版本节点只显示紧凑的上机状态，不增加行高；悬停或打开详情可查看整机数量、PM 数量及独立验证结论。**已上机不等于验证通过**，读取失败显示“未获取”，不冒充未上机。PM 可能沿用整机，也可能有独立特例。Lab 记录来自系统实际配置，不代表联网检测或真实硬件安装确认。观察时间不能充当安装时间：安装时间未知时，需要先明确登记实际升级，才能记录通过/失败结论。

验证是追加记录，不覆盖旧结论；机台离开 Lab、PM 移除或机台删除后，历史仍保留，当前使用数量则按实际情况更新。结果汇总取本测试轮次各整机/PM 记录，任何范围仍失败时显示失败；失败后仅改成“待验证”不会解除失败，必须在同一范围重新通过。没有未解决失败且存在最新通过记录才汇总为通过。通过一个范围不代表所有 Lab 范围都已验证。

## 6. 发布验证策略

默认 `false`：只记录 Lab 使用/验证，不增加旧环境的发布门槛。**默认值不表示已验证，也不是逐次审计豁免。** 当前不提供单次豁免按钮。

确认团队开始执行验证流程后，在 Host 配置中合并以下配置，并重启 Host；不要覆盖已有连接串或其他配置：

```json
{
  "ConfigHub": {
    "Laboratory": {
      "RequirePassedValidationForRelease": true
    }
  }
}
```

也可设置环境变量 `ConfigHub__Laboratory__RequirePassedValidationForRelease=true`。本地配置默认在 `%LOCALAPPDATA%\ConfigHub\appsettings.local.json`；正式服务配置由既有部署方式管理。

开启后，直接登记为已发布/维护中、版本转发布、勾选测试版本生成基线、超级维护转发布均不能绕过校验。当前测试轮次需要至少一项通过，且各范围最新验证没有失败；版本重新进入测试必须有新一轮证据。既有已发布版本不会被追溯改写，已经冻结的基线不变。

源码本地升级可在停止旧 Host/Worker 后，在仓库根目录运行原入口：

```powershell
.\start-local.cmd -RunMigrations
```
